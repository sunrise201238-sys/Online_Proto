An address is the last part of `https://claude.ai/artifact/<address>`. The artifacts are private to their owner. "Last
published" is read from the version each artifact served (the number before the dash in `served.tsv`'s `version` column is the
time of that publish, in Unix seconds).

## The two lists

- `served.tsv`: one line for each thing an artifact served, 221 lines: the artifact, its address and version, the
  piece (`index.html` for a page, `project/<file>` for a file of a board set or of the deck, `upload /_blob/<id>` for a
  picture, `store motions/<unit>` for a saved pick), its size and sha256 as served, the file here that holds it, and how the
  two relate.
- `copies.sha256`: the 219 files here that hold those pieces, with their sha256. From the root of the
  checkout, `sha256sum -c docs/artifacts/copies.sha256` says whether every copy is still what it was.

Three relations appear in `served.tsv`:

- **same bytes** (208 pieces): the file here is the served file, byte for byte.
- **the served page without the host's wrapper** (one piece, Line-up Card Crop): claude.ai serves a page that was published
  as a bare body inside two lines of its own, a head line before it (for this page 531 bytes: the doctype, the viewport, a
  base style) and `</body></html>` after it. `line_up_card_crop.html` is what stands between those lines, which is the file
  its build script writes. The other pages here are kept as served, with those two lines where the artifact had them; the
  head line is not the same on every page, the host having changed it over the months.
- **the same document, laid out over lines** (ten pieces): a motion map's saved pick is a document in the artifact's store, not
  a file. `picks/<unit>.json` is that document, the same keys and values in the same order, written over several lines.
  Kei's and Haruka's stores hold no document.

## What is not here

- **The types' own files.** The three board sets were made on claude.ai's Design type and the deck on its Slides type. Such an
  artifact also serves the type's own program (`artifact-type/…`, `SKILL.md`, `index.html`: 34 files for the UI boards, 22 for
  each colour board set, 40 for the deck). Those belong to the type, come with any new artifact started from it, and are not
  kept. What a person made is under `project/` and in the uploads, and all of that is here.
- **Fonts.** Three of the pages (Line-up Card Crop, Bloom Range, 指揮模式上線評估), every board and the deck load their fonts
  from Google Fonts by address. Without a network they fall back to the system's fonts.
- **Comments.** None of the twenty-two artifacts has a comment thread.
- **Other stores.** Only the motion maps keep data of their own in a store, and that is the picks above. The Slides type
  declares a store with a collection `notes`: the deck's is empty. The Design type declares a store as well; its own
  description names no collection in it for a canvas's content, which is the files and the uploads, and nothing was read
  from it.
- **Earlier versions.** An artifact keeps the versions it was published with; only the one it served on 2026-11-20 was read.

## Putting one back

Each folder's README says how: a page is published as it is; a board set is started from the Design type, its files go under
`project/` and its pictures are uploaded again (`shared/tools/design-samples/README.md`); the deck is started from the Slides
type (`shared/tools/league/README.md`); a motion map's pick is written back to the document `motions/<unit>` of the new
artifact's store (`shared/tools/motion-maps/README.md`).
